# StockTrace DB 모델 초안

2026-11-27 · 논의용 · [API 명세](./api-design.md) · [피그마 전체 앱 프로토타입](https://www.figma.com/design/vffh5rjHdioDiQrClJd0XX/StockTrace?node-id=87-874)

## 1. 저장 위치와 접근 경로

**확정한 서비스 범위는 국내 상장 주식 전체 검색과 전체 상장기업의 임원·주요주주 소유상황보고(D002) 조회다.** 코스피·코스닥·코넥스의 상장 주식(보통주·우선주 등)을 대상으로 설계한다. 공시 유무와 관심 등록 여부는 검색 조건에 영향을 주지 않는다.

API 명세에서 정한 계정·관심 종목 동기화에 더해, 이 초안은 **Kotlin 서버가 수집한 공용 데이터도 Cloud Firestore에 보관**하는 구성을 제안한다. 로컬에서 실행하는 서버는 재시작 후에도 같은 공시와 가격을 제공할 수 있다. Android에서는 로그인과 하트에 Firebase SDK를 사용하고, 공용 데이터는 기존 REST API로 읽는다.

| 저장 위치 | 저장하는 값 | 쓰는 곳과 읽는 곳 |
|---|---|---|
| Firebase Authentication | UID, Google 이름·이메일·프로필 | Android 로그인과 마이 화면에서 사용한다. 현재 화면에는 별도 회원 프로필 문서가 필요하지 않다. |
| Cloud Firestore | 관심 관계, 국내 상장 주식, 거래일별 종가, 고시일별 지표, 공시와 원문 변동 행 | 앱은 본인 관심 관계를 구독·등록·해제한다. Kotlin 서버는 공용 자료를 수집·조회하고 전체 관심 관계로 인기 순위를 계산한다. |
| Android Room | 마지막으로 성공한 화면별 API 응답과 저장 시각 | 기기에서 오프라인 화면을 복원한다. 시세 기준일과 기기 저장 시각을 각각 표시한다. |

## 2. Firestore 문서

| 문서 경로 | 문서 한 건의 의미 | 주요 필드 |
|---|---|---|
| `stocks/{stockCode}` | 국내 상장 주식 한 종목 | `stockName, companyName, isin, market, corpCode?, securityType, listingStatus, catalogAsOf, latestQuote`. 최신 시세 요약에는 거래일, 종가, 직전 거래일 종가, 공급처 등락액·등락률, 거래량, 출처, 성공 수집 시각이 들어간다. |
| `stocks/{stockCode}/dailyQuotes/{tradingDate}` | 한 종목의 한 거래일 시세 | `priceKrw, previousCloseKrw, changeKrw, changePercent, volumeShares, source, fetchedAt`. 최신 요약과 30일 차트의 공통 원자료다. |
| `marketIndicators/{symbol}` | KOSPI·KOSDAQ·USD_KRW 각각의 최근 수집 상태 | `unit, source, status, referenceDate, value, changeValue, changePercent, asOf, fetchedAt`. 지표별로 마지막 성공 기준일을 유지한다. |
| `marketIndicators/{symbol}/observations/{referenceDate}` | 한 지표의 한 기준일 관측값 | `value, changeValue, changePercent, asOf, fetchedAt, source`. 환율은 직전 고시일과 비교한다. |
| `collectionWindows/{windowId}` | D002 접수 기간별 시장 전체 수집 기록 | `from, to, reportType, status, nextPage, lastSuccessAt`. 날짜 구간별 페이지와 정정·철회 대조 완료 여부를 관리한다. |
| `disclosures/{receiptNo}` | DART 접수번호 하나에 대응하는 보고서 | `stockCode, corpCode, companyName, filedOn, reportAsOf, reporterName, relationship, position, ownershipPercent, previousShares, currentShares, holdingDeltaShares, direction, isCorrection, isListEligible, latestReceiptNo, sourceUrl, activeRowVersion, tradeRowCount, tradePreview`. 회사명·보고자·직책은 공시 당시 값이다. |
| `disclosures/{receiptNo}/rowSets/{version}/rows/{rowNo}` | 해당 원문에서 확인한 개별 변동 한 행 | `rowNo, changedOn, securityType, reason, deltaShares, unitPriceKrw`. 원문 순번을 정수로 저장하고 상세는 이 순번으로 읽는다. `version`은 파싱 결과를 재처리할 때 완성된 행 묶음을 가리킨다. |
| `users/{uid}/favorites/{stockCode}` | 계정 하나가 현재 관심 등록한 종목 하나 | `stockCode, createdAt`. 문서 경로가 복합 키 역할을 한다. 목록의 가격과 거래일은 해당 코드의 시세 응답을 결합한다. |

종목코드(6자리), DART 기업코드(8자리), 접수번호(14자리)는 앞자리 0을 보존하는 문자열이다. 거래일·접수일·변동일·고시일은 한국 날짜의 `YYYY-MM-DD`, 수집·등록 시각은 Firestore Timestamp다. 수량·원 단위 종가는 64비트 정수다. 신고 단가·환율·비율은 공급처 십진값을 정규화한 문자열로 보관하고 서버에서 BigDecimal로 비교·계산해 API의 JSON number로 반환하는 안이다. 문자열 사전순으로 등락률을 정렬하면 틀리므로 순위는 Kotlin에서 수치로 정렬한다.

## 3. 화면별 조회와 갱신

| 화면 | 읽기·쓰기 방식 |
|---|---|
| 홈·전체 순위 | 거래량·상승·하락은 같은 거래일에 유효한 지표가 있는 상장 종목으로 계산하고 거래일별 정렬 결과를 서버에서 재사용한다. 인기 첫 페이지는 서버가 전체 `favorites` 컬렉션 그룹을 읽고 상장 종목별로 문서 수를 센다. 1개 이상만 건수 내림차순, 동률은 코드 오름차순이다. UID는 응답에 포함하지 않는다. 소규모 시연을 전제로 한 집계이고 읽기량은 전체 하트 수에 비례한다. |
| 검색·관심 목록 | 완전 수집한 기준일의 KRX 종목 목록으로 서버 메모리에 검색 인덱스를 만든다. 종목명·법인명 부분 일치와 이름·코드 정확 일치를 처리하고 새 기준일 인덱스가 완성되면 교체한다. 정확 일치를 앞에 둔다. 하트 목록은 코드 50개 단위로 시세를 일괄 요청하고 코드로 합친다. 시세 미제공이어도 관심 관계는 유지한다. |
| 종목 상세 | `latestQuote`와 오늘 포함 최근 30일의 `dailyQuotes`를 읽는다. 종가 문서와 최신 요약은 한 트랜잭션에서 반영하고, 과거 날짜 재수집이 최신 거래일을 되돌리지 않게 비교한다. 없는 거래일은 점을 만들지 않는다. |
| 공시 목록·종목별 공시 | `isListEligible == true`, 선택한 종목의 발행사 `corpCode`, 접수일 범위로 읽는다. 서버는 수집 결과를 게시할 때 같은 버전의 목록 인덱스와 방향별 건수를 구성해 재사용한다. 방향 적용 전 건수를 제공하고 접수일·접수번호 내림차순으로 페이지를 읽는다. 홈 최근 2건도 같은 유효성 기준을 쓴다. |
| 공시 상세 | 지정한 접수번호와 해당 문서가 가리키는 행 묶음을 읽는다. 최대 두 행은 목록용 미리보기에도 보관한다. 직전·이번 수량으로 보유 변화율을, 적격 거래 행의 단가와 조회 시점의 동일 종목·주식 종류·가격 기준 종가로 가격 차이를 계산한다. 가격 기준 검증 근거를 확보하지 못하면 `BASIS_UNVERIFIED`로 제공한다. |
| 지수·환율 | 서버는 세 지표를 개별 갱신하고 날짜별 관측값과 최신 요약을 함께 반영한다. 갱신 실패 시 기존 값이 있으면 기준일을 유지하고 `DELAYED`, 성공 이력이 없으면 `UNAVAILABLE`이다. |
| 오프라인·오류 | Room의 `response_cache(cacheKey PK, payloadJson, cachedAt)`를 제안한다. 캐시 키에 자원·식별자·정렬·기간·방향·페이지 조건을 포함한다. 홈 영역별 마지막 성공값을 복원하고 실패 응답은 덮어쓰지 않는다. 관심 표시는 현재 UID에 묶고 로그아웃 시 구독과 표시를 해제한다. |

**페이지 일관성.** 세 목록(검색·순위·공시)은 첫 페이지 시점의 정렬 결과와 응답에 필요한 값·건수를 로컬 서버 메모리에 짧게 보관한다. 커서는 스냅샷 식별자·조건·페이지 위치에 연결한다. 같은 커서를 재시도하면 같은 페이지가 나온다. 새 첫 페이지는 최신 데이터를 조회한다. 서버 재시작 또는 보관 시간 만료 시 기존 커서는 명세대로 410을 반환한다. 초기 조회 후보 인덱스는 공시의 `isListEligible + filedOn`과 `isListEligible + corpCode + filedOn`이다. 행과 차트는 부모 경로 안에서 순번 또는 날짜로 조회한다.

**쓰기 권한.** 앱은 본인 UID의 관심 문서만 읽고 쓸 수 있다. 등록 시 경로와 필드의 종목코드가 같고 지원하는 종목인지 검사하고, 등록 시각은 서버 기준으로 생성한다. 이미 등록된 종목의 재등록은 기존 등록 시각을 유지한다. 해제는 같은 경로의 문서를 삭제한다. 서버 SDK의 공용 자료 쓰기와 관심 집계 권한은 서버 계정 IAM으로 관리한다. [Firebase 보안 규칙](https://firebase.google.com/docs/firestore/security/get-started) · [컬렉션 그룹 조회](https://firebase.google.com/docs/firestore/query-data/queries#collection-group-query)

### 전체 종목과 공시를 연결하는 기준

**공시 수집·보관 정책(확정).** 최초 수집을 시작한 한국 날짜를 D로 고정하고, 전체 상장기업의 D002 접수분을 D−89일부터 D일까지 양끝을 포함해 수집한다. 이 구간을 수집 기록에 남겨 재시작해도 시작일을 유지한다. 이후 마지막 완료 구간부터 새 접수분을 이어서 누적한다. 당일은 추가 접수가 가능하므로 다시 조회하며 접수번호가 같으면 기존 건을 갱신한다. 90일을 지난 공시도 계속 보관한다. 초기 범위 밖의 원문 검증 표본은 테스트 데이터로만 사용한다.

- KRX 상장종목정보를 기준일별로 끝까지 읽어 시세·공시가 없는 종목도 검색에 넣는다. 신규·상장폐지 판정은 완전 수신한 기준일 목록끼리 비교한다. 종목코드와 ISIN으로 주권을 식별하고 DART 기업코드로 발행사를 연결한다. 보통주와 우선주는 각각의 이름·시세·하트를 갖고 같은 발행사의 공시 목록을 공유한다. 공시 행의 가격 비교는 원문 증권 종류를 확인한 경우에만 해당 종목 종가를 사용한다. 발행사 연결을 확인하지 못한 종목도 검색에서 유지한다. [KRX상장종목정보](https://www.data.go.kr/data/15094775/openapi.do)
- OpenDART 목록을 기업코드 없이 짧은 접수일 구간별로 조회하고 D002의 마지막 페이지까지 순회한다. 상장기업 건을 접수번호로 중복 제거하고 새 공시가 있는 기업의 보유 정보와 원문을 보강한다. 실패한 구간은 이어서 수집하고 최신 구간을 다시 대조한다. 진행 중인 구간은 완료 기간에 포함하지 않는다. 정정으로 이전 구간의 유효본이 바뀌면 이전 목록과 집계도 갱신한다. [OpenDART 공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)
- 요청 기간의 목록 수집이 완료되고 발행사도 확인됐을 때만 빈 결과를 ‘해당 기간 공시 없음’으로 표시한다. 미완료·매핑 미확인은 해당 공시 영역에서 재시도할 수 있게 한다. 목록 확보 후 상세 행만 미수집이면 보고서와 원문 링크를 먼저 제공한다.

## 4. 실제 공시로 본 저장 단위

덴티스의 접수번호 `20260727000407`에는 7월 22일 장내매수가 두 행 있다. 공시 목록에서는 보고서 한 건이고, 상세에서는 아래 두 거래다. [원문 대조 기록](./공시-단가-검증.md)

| 같은 보고서 안의 행 | 변동일 | 수량 | 주당 신고 단가 |
|---|---|---:|---:|
| 첫 번째 매수 행 | 2026-07-22 | +2,000주 | 2,365원 |
| 두 번째 매수 행 | 2026-07-22 | +1,200주 | 2,480원 |

- 원문을 아직 읽지 못했으면 `tradeRowCount=null`이다. 확인 결과 대상 행이 없으면 0이다. 재처리 시 새 버전의 행을 모두 기록한 뒤 보고서의 버전·행 수·미리보기를 한 번에 교체한다. 실패한 수집이 이전에 열 수 있던 상세를 훼손하지 않는다.
- 정정본은 별도 접수번호로 보존한다. 최종보고서·철회 여부를 대조해 유효 목록과 집계에는 최신 유효본만 넣고 이전 상세는 해당 접수번호로 계속 연다. 연결이 확인된 경우에만 `latestReceiptNo`를 채운다.
- 가격이나 단가가 없으면 null, 확인된 0은 0이다. 보고서의 순증감은 같은 보고서의 직전·이번 보유 수량에서 구한다. 수증과 매수가 섞인 보고서에서도 개별 매수 수량과 구별할 수 있다.

### 기업 거래 행과 홈 순위

- 보고서에 `reporterRole`(공개 당시 임원 여부·주요주주 여부), `reporterKind`(개인·기관·미확인), `reporterKey?`(동일인 확인 시), 변동 행에 `tradeType`(장내매수·장내매도·수증·기타·미확인)과 `tradedStockCode?`를 추가한다. 원문의 직책·관계·사유는 그대로 보관한다. 발행사 보통주와 우선주를 혼동하지 않도록 실제 증권 종류가 매칭된 종목에 금액을 귀속한다.
- 홈은 최근 30일 **접수일**을 기준으로 최신 유효 보고서의 활성 행 중 임원으로 확인된 개인의 장내거래만 읽는다. 종목·매수/매도별로 `Σ(|변동 수량| × 신고 단가)`를 십진수로 계산한다. 유효한 수량·양의 단가가 있는 행을 사용하고, 같은 임원의 반복 거래는 모두 합산하되 사람 수는 한 번 센다. 인원 식별이 불충분하면 확정 인원처럼 표시하지 않는다. 종목 상세에서 순위를 눌렀을 때 같은 기간·방향·집계 대상의 근거 행을 제공한다.
- 덴티스 표본의 두 행은 2,000 × 2,365 + 1,200 × 2,480 = **7,706,000원**이다. 두 행이 같은 적격 임원에게 속하면 매수 임원은 1명이다. 수증만 있는 보고서는 보유량 증가 및 거래 유형 ‘전체’에 보이고 장내매수액에는 기여하지 않는다. 원문 행이 미확보된 기간은 집계 범위를 표시하거나 순위 제공을 보류한다.
- 서버가 수집분 게시 시 활성 행으로 조회용 목록과 순위를 생성해 재사용한다. 정정·철회·재파싱 시 이전 기여분을 제거하고 같은 버전의 목록과 합계를 게시한다. 보고서에 저장된 미리보기 두 행만 합산하면 세 번째 이후 거래가 누락된다.

### 의원 재산공개용 문서 제안

| 문서 경로 | 주요 필드 | 조회 목적 |
|---|---|---|
| `parties/{partyId}` | `displayName, logoKey?` | 정당의 안정적인 식별자와 표시 자산. ‘그 외·무소속’은 화면 묶음으로 처리하고 실제 소속과 무소속 여부를 보존한다. |
| `assetReleases/{releaseId}` | `publicYear, referenceDate, publishedOn, previousReleaseId?, sourceUrl?, datasetKind, coverageStatus` | 공개 연도와 재산 기준일을 구분한다. 시안의 2026년 공개 예시 기준일은 2025-12-31이다. 예시 자료와 실제 자료는 서로 다른 데이터셋에 두고 같은 합계에 넣지 않는다. |
| `assetReleases/{releaseId}/members/{memberId}` | `nameAtRelease, partyIdAtRelease?, affiliationStatus, reportId?, reportLinkStatus` | 동일한 의원의 연도 간 식별에는 안정적인 ID를 사용한다. 이름이 같은 의원을 구분하며, 탈당·당적 변경 후에도 과거 명단을 재현한다. 신고서 미연결과 본인 보유 0건을 구분한다. |
| `assetReleases/{releaseId}/reports/{reportId}` | `memberId, sourceDocumentId, sourceUrl?, sourceLocator?, revision, status` | 의원별 원문과 정정 이력을 추적한다. 명단에서 유효본을 가리키고 정정 이전 신고의 행을 중복 집계하지 않는다. |
| `assetReleases/{releaseId}/reports/{reportId}/holdings/{rowId}` | `memberId, ownerRelation, ownerKey?, reportedStockName, stockCode?, shares?, sourceRowRef` | 원문 보유 행을 보존한다. 주식 종류·명의를 확인해 기존 종목과 연결한다. 매핑되지 않은 원문 행도 신고 상세에서 읽을 수 있다. |

- 정당별 보유 종목 수는 본인 보유가 확인된 고유 종목 수, 종목별 인원은 고유 의원 수다. 같은 의원의 동일 종목 행은 수량을 합산한다. 가족분은 별도 상세에 표시한다. 공개 당시 소속을 기준으로 5개 정당과 ‘그 외·무소속’에 배치하고, 소속 미확인은 실제 무소속과 구별한다. 2025·2026 화면의 자료를 같은 방식으로 조회한다.
- 개인 증감은 같은 의원·명의·종목에 대해 직전 공개와 이번 공개의 수량이 모두 확인될 때 계산한다. 직전 320주이고 이번에 수량이 빠졌으면 ‘이번 수량 미확인’이다. 명시된 0주는 계산에 쓸 수 있다. **정당 증감**은 각 공개 시점의 소속을 적용한 본인 보유 합계 간 차이다. 비교할 범위가 확인될 때만 제공하고 소속 의원 변동이 반영됨을 표시한다.
- 검색은 선택한 공개 회차의 명단에서 이름 앞부분과 정당으로 조회한다. 서버는 공개 회차 게시 시 본인 보유 자료로 정당→종목, 종목→정당·의원 목록을 함께 구성할 수 있다. 처음부터 합계마다 별도 원본 문서를 만들 필요는 없다. 로고는 종목 또는 정당 키에 공통 자산을 연결하고 자료가 없을 때 기본 아이콘을 쓴다.

### API와 실자료 대조 항목

검토한 로컬 API 문서에는 종목 일반 순위와 보고서 단위 `direction`이 정의돼 있다. 새 화면에는 임원 거래액 순위·근거 거래 행, 공개 회차 선택, 정당·종목별 보유, 의원 검색·명단·신고 비교 조회가 추가로 필요하다. D002의 최초 90일 수집과 이후 누적 정책은 기업 공시에 적용하고, 의원 신고는 공개 회차별로 수집한다. 의원 실자료에서는 연도 간 동일인 매칭, 공개 당시 소속, 본인·가족 구분, 보유 수량과 종목 식별·원문 연결 가능성을 확인해야 한다. 피그마의 가상 의원·수량은 실자료 검증에 사용하지 않는다.
